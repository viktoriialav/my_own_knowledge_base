## Команды Git

___
### Настройка Git
- `git config --global user.name "[Name Surname]"` - установка имени
- `git config --global user.email "[example_email@gmail.com]"` - установка e-mail адреса

- `git config --list` - выводит список текущих настроек.

- `git config --system core.longpaths true` - решение проблемы "Filename too long" для Windows.
- `git config --global http.sslVerify false` - отключение проверки SSL.


___
### Основные команды Git:

- `git init` - создаёт в текущем каталоге новый подкаталог с именем .git, содержащий все необходимые файлы репозитория. На этом этапе ваш проект ещё не находится под версионным контролем.
- `git clone [url]` - клонирование репозитория в текущий каталог.
- `git clone [url] [catalog_name]` - клонирование репозитория в каталог `catalog_name`.
- `git status` - отображает измененные файлы в рабочем каталоге, подготовленные для вашей следующего коммита.
- `git add .` - добавление всех файлов в текущем каталоге в индекс (добавление под версионный контроль).
- `git add [folder_name/]` - добавляет весь каталог в индекс.
- `git remote add [alias] [url]`
- `git commit -m "[Initial commit]"` - фиксация изменений с комментарием.
- `git commit -a -m "[Initial commit]"` - добавление всех уже отслеживаемых файлов в индекс и осуществление коммита.
- `git push -u origin [branch_name]` (`-u` = `-set-upstream`) - отправка изменений в удаленный репозиторий.
- `git pull` - извлекает данные с сервера, с которого вы изначально клонировали, и автоматически пытается слить их с кодом, над которым вы в данный момент работаете.
- `git fetch [repository_alias]` - связывается с указанным удалённым проектом и забирает все те данные проекта, которых у вас ещё нет. Не сливает их с какими-либо вашими наработками и не модифицирует то, над чем вы работаете в данный момент. Вам необходимо вручную слить эти данные с вашими, когда вы будете готовы.
- `git log`
- `git checkout [commit_hash]` - переключиться на указанный коммит.

___
### Отмена операций
- `git checkout -- [file_name]` - возращение файла к состоянию как в последнем коммите.
- `git restore [file_name]` - возращение файла к состоянию как в последнем коммите (альтернатива предыдущему).
- `git restore --staged [file_name]` - отмены индексации файла.

___
### Просмотр истории коммитов
- `git log` - показывает все коммиты, сделанные в репозитории в обратном хронологическом порядке.
- `git log -- [path/to/file]` - показывает только те коммиты, в которых были изменения файлов, указанных в репозитории.
- `git log --pretty="- %ad | %h | %s" --no-merges --date=format:"%Y-%m-%d %H:%M:%S" >commites.txt` - сохраняет в файл информацию о коммитах в определенном виде, которые были сделаны в исходном коде за все время и не были коммитами слияния

Дополнительные опции для `git log`:
  - `-p` (или `--patch`) - показывает патч для каждого коммита.
  - `--stat` - показывает статистику изменённых файлов для каждого коммита.
  - `--shortstat`- отображает только строку с количеством изменений/вставок/удалений для команды `--stat`.
  - `--name-only`- показывает список изменённых файлов после информации о коммите.
  - `--name-status` - показывает список файлов, которые добавлены/изменены/удалены.
  - `--abbrev-commit` - показывает только несколько символов SHA-1 чек-суммы вместо всех 40.
  - `--relative-date` - отображает дату в относительном формате (например, «2 weeks ago») вместо стандартного формата даты.
  - `--graph` - отображает ASCII граф с ветвлениями и историей слияний.
  - `--pretty` - показывает коммиты в альтернативном формате. Возможные варианты опций: `oneline`, `short`, `full`, `fuller` и `format` (с помощью последней можно указать свой формат).
  - `--oneline` - cокращение для одновременного использования опций --pretty=oneline --abbrev-commit.

Опции для ограничения вывода для `git log`:
  - `-(n)` - показывает только последние n коммитов.
  - `--since`, `--after` - показывает только те коммиты, которые были сделаны после указанной даты (`2.weeks`, `2008-01-15`, `2 years 1 day 3 minutes ago`).
  - `--until [date]`, `--before [date]` - показывает только те коммиты, которые были сделаны до указанной даты.
  - `--author [author's name]` - показывает только те коммиты, в которых запись author совпадает с указанной строкой.
  - `--committer [string]` показывает только те коммиты, в которых запись committer совпадает с указанной строкой.
  - `--grep [string]` - показывает только коммиты, сообщение которых содержит указанную строку.
  - `-S [string]` - показывает только коммиты, в которых изменение в коде повлекло за собой добавление или удаление указанной строки.

### Работа с ветками локально и  на удаленном репозитории
- `git branch [branch-name]` - создание новой ветки `branch-name` текущего коммита.
- `git branch [branch_name] -D` (`-D` = `--delete`) - удаление ветки `branch_name`.
- `git checkout [branch-name]` - преключение на ветку `branch-name`.
- `git checkout -b [branch-name]` - содание новой ветки и переключение на нее `branch-name`.
- `git branch` - вывод влез локальных веток (опции --merged и --no-merged могут отфильтровать этот список для вывода только тех веток, которые слиты или ещё не слиты в текущую ветку).
- `git branch --all`- вывод всех веток.
- `git branch -v` - посмотреть локальный коммит на каждой из веток.
- `git branch -M [initial_branch_name] [new_branch_name]` (`-M` = `--move`) - переименование любой ветки локально.
- `git push -u origin [new_branch_name]` (`-u` = `-set-upstream`) -->
  `git push origin --delete [initial_branch_name]` - переименование ветки удаленно с сохранением всех предыдущих изменений.
- `git remote set-url [old_repository_alias] [new_url]` - переименование удаленного репозитория локально (если предварительно в GitHub название было изменено).
- `git remote show [repository_alias]` - просмотр удаленного репозитория.


___
### Слияние
- `git merge [branch_name]` - слияние ветки, на которой мы сейчас находимся, с веткой `branch_name`.

### Reset
- `git reset` - c,hfcsdftn 
- `git reset --hard` - отменяет все  (отменить все незакоммиченное).
- `git reset --hard HEAD~1` - удаляет последний коммит, который еще не запушен (`HEAD~1` означает фиксацию перед головой).
- `git reset --hard HEAD~n` (отменить все незакоммиченное и откатиться на n-коммитов).

### Удаление файла
- `git rm [file_name]` - удаляет файл из рабочего каталога
- `git rm [file_name] --cached` - оставляет файл на жёстком диске, но перестать отслеживать изменения в нём

___
### Перемещение файла = Переименование файла
- `git mv [file_from] [file_to]` - перемещение файла из директории `file_from` в директорию `file_to`
- `git mv [current_name] [new_name]` - переименование файла

___
### Вычисление разницы
- `git diff` - разница между вашей рабочей копией и индексом.
- `git diff --staged` - разница между индексом и последним коммитом.
- `git diff [branchA]...[branchB]` - разница между между любыми двумя ветками.
___
### Отображение информации об объекте
- `git show` - отображает информацию о последнем коммите.
- `git show [object]` - отображает информацию о конкретном объекте (`commit_hash` etc.).

___
### Stash
- `git stash` - временное сохранение всех незафиксированных изменений с целью очистки рабочего каталога без необходимости фиксировать незавершённую работу в текущей ветке.
- `git stash pop` - применение сохраненных изменений
- `git stash list` - покажет список всех сохраненных изменений.
- `git stash apply` восстановит последние сохраненные изменения обратно в рабочий каталог.
- `git stash drop` - удалит последние сохраненные изменения из списка `stash`.

___
### Обновление GIT

- `git update-git-for-windows` - Windows
- `git update` - Linux
